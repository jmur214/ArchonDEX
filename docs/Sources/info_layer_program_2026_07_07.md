## LANE 1 — News (owner: D)

**1.1 Probe first (gates the lane)** — `scripts/probe_news_depth_t3xx.py`, writes to `data/intel/probe/`:
- **P1 depth:** earliest `created_at` for SPY/AAPL/TSLA from starts 2010/2015/2018/2020 → verdict `D-deep` (≤2016) vs `D-shallow` (≥2021).
- **P2 survivorship:** fetch delisted tickers pre-delisting (SIVB, FRC, TWTR, BBBY) → `S-clean` vs `S-biased`.
- **P3 breadth:** articles/ticker across cap terciles of the PIT universe (2022-06 sample).
- **Pre-registered gating:** `S-biased` → cross-sectional picking tests re-scoped to covered-survivors with an explicit bias flag (or cut; index/sleeve tests are immune); `D-shallow` → backtests limited to the covered window w/ honest-N, forward accrual becomes the panel's main value.

**1.2 The PIT news panel** — `intelligence/news_panel.py` + resumable backfill `scripts/build_news_panel_t3xx.py`. Monthly parquets `data/intel/news_panel/news_YYYYMM.parquet`; schema: `article_id, created_at, updated_at, symbols (KEPT), headline, summary, content (KEPT, html_to_text'd), source, url, author, ingest_ts, ingest_run_id`. PIT rule: features at t use only `created_at` < t decision time. Universe: PIT universe ∪ holdings ∪ delisted set ∪ special-situations tickers. **Daily forward append** as a post-reconcile pulse step (`scripts/run_paper_cloud_day.py`), S3 via `CloudState` — fail-open for trading (never blocks orders), degraded-flagged for measurement. Un-dormants `news_sentiment_v2`'s census condition.

**1.3 Pre-registered non-LLM tests** (ONE frozen doc; dictionary features only — PIT-clean): features in `intelligence/news_features.py` (`lm_sentiment` [LM word lists → `data/intel/lm_dictionary/`], `vader_sentiment` [reuse the edge's analyzer], `abn_news_volume` [vs trailing 63d], `novelty` [TF-IDF cosine vs trailing 21d — reuse `scripts/lazy_prices/similarity_t237.py`]). Tests, all interaction/conditional: **(a1)** news-volume × momentum; **(a2)** LM-sentiment × post-8-K drift (EDGAR-anchored via `data/edgar/8k/panel_8k_items.parquet` 183k rows — depth-immune); **(a3)** novelty × reversal (only if D-deep); **(b1)** aggregate news sentiment/volume as a sleeve sizing tilt (T-233-bound). N_trials = 3-4. Honest priors stated: published news effects are small/decayed; expected null-to-marginal; the panel's durable value = forward accrual + the judgment layer's feed.

## LANE 3 — LLM Judgment Layer (owners: E build, A evaluation)

**3.1 The Analyst service** — new package `intelligence/analyst/`: `context_builder.py` (day's news for holdings+watchlist, special-situations deltas, event-state + Kalshi Fed distribution, per-account portfolio state, yesterday's open predictions; deterministic serialization, SHA-256 hashed), `note_schema.py` (pydantic-validated versioned schema `analyst_note/v1`), `analyst_service.py` (**single structured call — no tools, no agent loop at stages 0-1**), `cost_governor.py`, `eval_harness.py`. Notes are **write-once** (`data/intel/analyst_notes/YYYY/analyst_note_YYYY-MM-DD[_rN].json`, S3-synced), carrying model_id (requested + served), prompt version + SHA-256, input-bundle hash, and machine-typed fields: `market_assessment, risk_flags, position_notes, special_situation_scores, predictions [{statement, probability, horizon, machine resolver}], hypothetical_actions [{account: shadow, symbol, set_weight, target_weight}], usage`. Runs daily as a final report-only pulse step (analyst failure never fails the pulse); a deeper weekly synthesis Fridays. **Cost:** efficient-tier (Haiku-class) daily + stronger-tier (Sonnet-class) weekly, exact model IDs pinned in a new `config/llm_settings.json` at build time from the live API; prompt caching; estimated ~$5-8/mo ≈ 5-10× headroom under the $20-50 budget; `cost_governor` enforces per-call max_tokens + a monthly accumulator (`llm.monthly_budget_usd: 30`) + `llm.kill_switch` — breach → fail-closed skip + heartbeat flag. Prompts live as versioned files in `config/prompts/analyst/`; every change is a version bump so the eval record segments by (model, prompt).

**3.2 Prompt-injection defense** (it reads adversarial text): (1) no tools/no loop; (2) enforced JSON-schema output + independent local re-validation — failure → no note (never a suspect note), raw archived for forensics; (3) data/instruction separation with a `suspected_prompt_injection` risk-flag convention (attacks become logged signal); (4) semantic firewall on outputs: symbol allowlist, weight/turnover/probability bounds — violations reject the *action* and are logged; (5) **red-team fixture suite** `tests/test_analyst_injection_t3xx.py` (override/schema-escape/symbol-smuggling/homoglyph payloads) = a stage-0 exit requirement; (6) no credentials/account numbers ever in prompts.

**3.3 The authority ladder** (paper only; each gate frozen before its clock starts):
- **Stage 0 — report-only (≥4 weeks):** notes + dashboard tab. Gate **G0**: ≥95% valid-note days, zero validation failures final 10 days, injection suite green, cost ≤ budget, ≥50 resolvable predictions. Operational gate only.
- **Stage 1 — the virtual LLM shadow book (≥6 months):** `paper_trader/llm_shadow_book.py`, the `btc_shadow.py` pattern generalized — consumes yesterday's validated `hypothetical_actions`, fills at today's close + honest haircuts (signal-t/fill-t+1 makes look-ahead structurally impossible), **full authority within the firewall** (any allowlisted US equity/ETF, ≤20%/name, gross ≤2.0, ≤50% NAV/day turnover), zero account cost, degraded-day parking, plus a **benchmark twin** (60/40 at the same haircuts) in the same file. Gate **G1** (the analyst's accuracy record IS the promotion evidence — **AMENDED 2026-07-07 per the T-293 adversarial review**, which showed the original form was base-rate-hedger-gameable: calibration alone is a hedger's pass): Brier on **≥150 resolved predictions** must beat, per category, BOTH the climatological baseline AND the **market-implied prior** (Kalshi rate-path odds for Fed predictions; market-derived priors elsewhere) with **skill-score ci_low > 0**; a **discrimination/resolution requirement** so a zero-resolution base-rate parrot fails; **gimme exclusion** (near-certain predictions can't pad the record); calibration slope [0.7, 1.3] retained as necessary-not-sufficient; **SECOND AMENDMENT 2026-07-08 (external research run, Q4):** the Brier comparison vs the market-implied baseline uses a **block-bootstrap CI on the differential, required to exclude zero**; the scoreable question set is **pre-registered per note-day** (every valid prediction auto-enters — no selective picking, no horizon-shopping); and the analyst's probabilities are additionally **recalibrated (isotonic/Platt) against its own resolved history** with BOTH raw and recalibrated Brier reported (RLHF'd models hedge toward 0.5 and are overconfident — ForecastBench/Halawi evidence); zero unflagged injection incidents + zero schema failures final month; no rising trend of firewall-violation *attempts*; directional performance (Δwealth > benchmark twin AND MaxDD ≤ twin +5pp) — the doc must state 6 months cannot support a skill claim; G1 promotes authority-on-paper, not belief.
- **Stage 2 — real paper-account authority: a 4th Alpaca paper account** (free; keys → Secrets Manager; zero contamination of the sleeve/offense/BTC experiments). **AMENDED 2026-07-08 (fresh-eyes finding #2): there is no "per-account pulse pattern" to clone yet** — `run_paper_cloud_day.py` is hardwired single-account, so the multi-account refactor is NET-NEW work owned by E's T-288 fleet build (the 4th account then rides that same generalization); and `CloudState` is a small-file sync, not an archive layer — growing stores (news panel, analyst notes) need a sizing check before being routed through it. New `LLMOrderConstructor` producing target weights only; the existing deterministic OrderManager/exec-gates/reconcile/heartbeat stack does everything else; `llm.kill_switch` checked pre-submission reverts the account to reconcile-only. Any *live* discussion = a fresh future pre-registration under the full MBL/DSR bar — out of scope here.

**3.4 Evaluation harness** — `eval_harness.py` runs daily post-prices: resolves expired predictions via their machine resolvers (price_above / relative_return / dd_exceeds / event_occurs → Kalshi settlements + the macro calendar), appends to append-only `data/intel/analyst_predictions.jsonl`, maintains rolling Brier + calibration-by-decile + per-category breakdowns → dashboard. Everything the model ever asserts is scoreable, versioned, immutable.
