# T-151 — safe-f / CAR25 (Bandy), reporting-first

## The demonstration numbers (2024 canonical book, run `307759e7…`)

Config: P(MaxDD > 20% over 504td) ≤ 5%, 1000 paths, 10d circular
blocks, seed 0, f via bisection on a SINGLE pinned resample matrix.

| account | safe_f | verdict @ current sizing | CAR25 @ safe_f | P(DD>20%)@f=1 | mdd95@f=1 |
|---|---:|---|---:|---:|---:|
| Roth (pre-tax) | **1.602** | UNDER-sized — headroom +60% | 3.6%/yr | 0.000 | 12.85% |
| taxable-IL (after-tax, T-141 model) | **0.273** | **OVERSIZED — excess 73%** | **−5.47%/yr** | 0.799 | 57.26% |

**The are-we-oversized answer is account-dependent — and that is the
finding.** On this record the pre-tax book sits comfortably inside the
Bandy envelope; the after-tax taxable book fails it decisively (a
79.9% probability of a >20% drawdown at current sizing, and a NEGATIVE
conservative growth estimate even at the safe fraction). This is the
third independent instrument to indict taxable deployment at current
turnover (T-141 tax>profit; T-148 tax channel 29× cost; now Bandy
sizing), and the first to quantify Roth headroom (+60%).

**Honesty caveats (printed by the demo, load-bearing):**
1. **Record-dependence:** 2024 contains no 20%+ episode, so the
   pre-tax tolerance binds loosely. The 26-yr record (MDD −59%) would
   bind FAR lower — likely safe_f < 1 pre-tax too. Any actual sizing
   decision uses the deep-window number; re-run the demo on a
   multi-decade run dir when one is on disk.
2. **Taxable magnitude leans overstated:** T-141's model debits the
   whole year's tax as ONE synthetic year-end day; block resampling
   replicates that lump across MC paths (mdd95 57% is lump-driven).
   The direction is honest; the point value is conservative-side.
   A quarterly-estimated-tax cadence in the tax model would tighten it
   (noted as an option if this metric ever gates anything).

## What was built

- **`backtester/safef_car25.py`** — `compute_safef_car25(daily_returns,
  SafeFConfig)`:
  - circular-block MC resample (default 10d blocks — serial correlation
    survives; same rationale as the project's block-bootstrap standard),
    `n_paths × horizon` index matrix drawn ONCE from the pinned seed;
  - levered return = `f × r_t` (f=1 reproduces current implicit
    sizing); per-path MaxDD; **safe_f** = max f with
    `P(MaxDD > dd_tolerance) ≤ dd_probability`, solved by bisection on
    the SAME paths (exceedance is monotone in f on fixed paths ⇒ exact
    to `f_tol`, zero MC noise between iterations — this is also what
    makes the half-vol ⇒ double-safe_f identity testable exactly);
  - **CAR25** = 25th-pct CAGR at safe_f; diagnostics at f=1
    (exceedance, mdd95, CAR25) + `headroom = safe_f − 1`;
  - **every default documented as a reconstruction, NOT verified Bandy
    parameters** (the research flagged this) — all configurable via an
    optional `safef_car25` block in backtest_settings.json;
  - T-141 fail-open contract (None fields + skip_reason; degenerate
    all-positive records cap at f_max with an explicit reason).
- **Producer wiring (T-141 pattern):** `_safef_report()` cached per
  instance; summary gains `safe_f`, `car25_pct`, `safef_detail`;
  both performance_summary.json writers inherit. Reporting-only —
  **nothing consumes these for sizing**; canon untouched by
  construction (post-hoc read of the equity record).
- **Contract suite:** keys added atomically — and doing so EXPOSED a
  latent scraper bug: `_scrape_compute_summary_keys`'s non-greedy
  `return\s*\{(.*?)\}` stopped at the first `}` (the close of the
  first nested dict comprehension), so any key added after
  `after_tax_detail` was invisible — the layer-2a guard would have
  silently passed stale constants forever. Fixed with balanced-brace
  extraction + top-level-key filtering (nested-dict keys no longer
  leak in either). The guard now guards.
