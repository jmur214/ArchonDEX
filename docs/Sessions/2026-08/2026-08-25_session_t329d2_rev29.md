## What was learned

- **A scheduler-side AccessDenied is invisible in Batch.** No FAILED job exists
  because the submit never arrives; the DLQ message count is the only artifact.
  The CLI user can read the COUNT but not the bodies (`sqs:ReceiveMessage`
  denied) — documented in the execution manual.
- **A dead-man alarm that goes ALARM at creation never re-alerts on the real
  miss.** `ai-trader-silent-stop` went ALARM on 08-20 (missing data = breaching,
  before any run was due) and sat there — so Monday's genuine miss produced NO
  state transition and NO new notification. The alarm was "working" and useless
  at once. Drill-menu addition: every new dead-man alarm needs a
  first-datapoint plan (or a deliberate OK-transition) so a later miss can fire.
- **The provisioner itself carried a revert-a-live-fix bug** (force-DISABLED on
  update). The template-vs-live doctrine applies to STATE fields, not just
  config fields.
