The v2 dashboard (`cockpit/dashboard_v2/`, the ONLY allowed dashboard) follows a strict 3-layer split that a new tab must mirror exactly.

**Why:** Separation of data-processing from view from reactive logic is a hard project rule (CLAUDE.md "separate data processing from UI logic"). The user/architecture treats `cockpit/dashboard/` as deprecated/forbidden.

**How to apply** — to add tab `<name>`:
- `utils/<name>_loader.py` — pure pandas/stdlib, dataclasses (`@dataclass(frozen=True)`), `Path`, graceful-missing (return a `found=False`/pending dataclass, NEVER raise), `lru_cache` keyed on a file-mtime token so the 2s pulse doesn't recompute. Whitelisted engine imports only (for the Paper tab: `core.census.assert_census_file`, `core.combined_candidate_scorecard`).
- `tabs/<name>_tab.py` — exposes `<name>_layout` (a fn returning a Dash tree). Declares STATIC shells + empty output containers (`html.Div(id="...")`); reactive content is filled by callbacks. Import styling from `utils/styles.py` (`CARD_STYLE`, `SECTION_HEADER`, `COLORS`).
- `callbacks/<name>_callbacks.py` — exposes `register_<name>_callbacks(app)` with one `@app.callback`. Keep a module-level pure `compute_<name>_view()` that returns the output tuple (testable without the Dash wrapper — the capital_allocation tab does this and it's the validated pattern). Render helpers are module-level `def`s that turn loader dataclasses into components and contain NO data processing.

**app.py wiring = exactly 4 edits** (app.py lives INSIDE dashboard_v2, so editing it is allowed): import the layout; add a `dcc.Tab(label=..., value="tab-<name>", style=tab_style, selected_style=selected_tab_style)`; add `"tab-<name>": <name>_layout` to the `layouts={}` dict passed to `register_shared_callbacks`; import + call `register_<name>_callbacks(app)` in the registration block.

**Live refresh:** there's a single shared `dcc.Interval(id="pulse", interval=2000, n_intervals=...)` (disabled unless `--live`). A tab refreshes by taking `Input("pulse","n_intervals")` with `prevent_initial_call=False` (renders on tab open too). Tab content is swapped by `register_shared_callbacks` from the `layouts` dict — individual tab callbacks just target their own output ids.

**Construction smoke test:** `python -c "from cockpit.dashboard_v2.app import create_dash_app; create_dash_app(); print('APP OK')"` (use `.venv/bin/python` — the IDE language server points at homebrew 3.14 without dash; its "Cannot find module dash" errors are noise). Launch: `python -m cockpit.dashboard_v2.app --live --port 8050`.

**Testing a tab (validated 2026-07-02, tests/test_dashboard_paper_tab.py):** mirror tests/test_capital_allocation_dashboard.py — autouse `monkeypatch.chdir(REPO_ROOT)` + `cache_clear()` every module lru_cache before AND after each test. To test absent-data degradation, `monkeypatch.chdir(tmp_path)` inside the test (relative-path loaders then see an empty world — no mocking needed). To assert on rendered copy/column order, walk the component tree with small helpers: `_walk_text(node)` recursing `.children` collecting str leaves, and `_find_datatables(node)` matching `type(node).__name__ == "DataTable"` then reading `.columns` ids. Do NOT `json.dumps(layout.to_plotly_json(), default=str)` — component reprs truncate. Testing `render_*` helpers with a hand-constructed loader dataclass avoids ever triggering the slow bootstrap path (whole suite runs in ~1.6s).

**Patterns validated in the 2026-07-02 Forward Clocks rework (intel_tab → situations feed + BTC shadow):**
- *Rolling-date cache key*: when a loader derives a "live within N days" flag, key the `lru_cache` on `(file_mtime, cutoff_iso)` — not mtime alone — so a long-running dashboard rolls the window at midnight instead of serving a stale flag. Make `today: date` an injectable param of the public wrapper for pinned-cutoff tests.
- *Rename-safe parallel integration*: when a workstream renames a layout fn but another agent owns app.py, export the new name AND alias the old (`create_intel_layout = intel_layout`) so the app keeps constructing before the integrator relabels. Zero-cost; kept the construction smoke green mid-overhaul.
- *DataTable markdown links* in dark mode: column `{"presentation": "markdown"}` + `css=[{"selector": ".dash-cell a", "rule": "color: <accent>;"}]` (default link blue is unreadable on the dark bg).
- *Filter callbacks*: `dcc.Input(debounce=True)` for free-text search so typing doesn't fire a callback per keystroke; combine pulse + filter controls as Inputs on ONE callback with a pure `compute_<x>_view(...)` body — filtering stays instant because the loader hit is cache-served.
- *Honest-framing strings as module constants* in the tab module (e.g. `SITS_FRAMING_PRIMARY = "★ DATA COLLECTION, 0 N_trials, NO edge claim"`) — tests assert the verbatim strings, so honesty labels can't silently drift.
- *Engine-object reuse in loaders*: to render another module's computed status (e.g. `BtcShadowTracker.forward_gates()`), call the object itself inside a lazy-import try/except → `None`; never re-derive gate logic in the dashboard.

**Legacy parent regroup (2026-07 overhaul, WS5):** the Analytics parent (`tab-analytics-parent`, `tabs/analytics_parent_tab.py`) is now "Legacy — Old World"; its `analytics-sub-tabs` values are `dashboard` (default, Equity Book), `backtest`, `trading` (retired notice), `performance`, `governor`, `evolution` (Edge Graveyard), `capital_allocation`, `feature_foundry`, rendered by `render_analytics_sub_content` (a CLOSURE inside `register_analytics_navigation_callbacks` — not importable; its layout imports ARE module-level, so test via `nav.dashboard_layout` etc.). CRITICAL: when a tab demotes to a sub-tab, its `register_*_callbacks(app)` call must STAY in app.py — sub-tab rendering still needs the callbacks registered; only the top-level `dcc.Tab` + layouts-dict entry move.

**Post-redesign nav (integrated 2026-07-02, mission-control home):** 8 top-level tabs in order — Home `tab-home` (DEFAULT, `dcc.Tabs(value="tab-home")`, `home_layout` mission-control page), Execution `tab-exec` (`execution_parent_layout`; ops/paper demoted to sub-tabs `exec-sleeve`/`exec-paper` under `exec-sub-tabs`/`exec-sub-content`), Forward Clocks `tab-intel`, Advisor `tab-advisor`, Research Record `tab-research`, Command Center `tab-command`, Legacy (Old World) `tab-analytics-parent`, Settings `tab-settings`. `tab-ops`/`tab-paper` no longer exist as top-level values or layouts-dict entries (but `register_ops_callbacks`/`register_paper_callbacks` STAY in app.py — sub-tab rendering needs them). `tab-dashboard`/`tab-backtest`/`tab-trading` no longer exist as top-level values or layouts-dict entries (Legacy sub-tabs only). app.py integration additions beyond the 4-edit rule: `register_archon_template()` is the FIRST statement in `create_dash_app()` (theme default before any figure), and `html.Div(id="global_demo_banner", className="demo-banner-slot")` sits between the header and the mode_state Store (always-rendered so the demo-banner callback fires on initial load even with the pulse disabled). Boot-check idiom: `create_dash_app(live=False)` then `len(app.callback_map)` (32 as of integration) — duplicate callback outputs fail here. `analytics_callbacks.py` stays deliberately UNREGISTERED (orphaned by design, pending archive). Pure compute-view signatures: they do NOT take the pulse `n_intervals` arg — the Dash wrapper drops it (e.g. `compute_situations_view(class_value, live_values, search)`, `compute_btc_view()`, `compute_ops_view()` → 13-tuple post-WS-E: the 6th slot is the chart's DEMO badge). Ops/Paper also render as sub-tabs of the Execution parent (`tabs/execution_parent_tab.py`, ids `exec-sub-tabs`/`exec-sub-content`, values `exec-sleeve`/`exec-paper`). Run tests via `.venv/bin/python -m pytest` (no conftest — bare `pytest` can't import `cockpit`).

**Headless integration smoke (validated 2026-07-02, replaces browser click-through):** (1) construct the app under a socket-connect-raises monkeypatch (proves zero-network boot); (2) call every layout fn + every Legacy sub-layout fn; (3) run every pure `compute_*_view()` against on-disk data and assert on `_walk_text` output; (4) dup-id sweep — recursively collect `.id` strings per rendered tree, fail on intra-tree dups or collisions with the app-shell ids (cross-tree sharing is only fatal if simultaneous); (5) boot the real server and, per tab value, `curl -X POST /_dash-update-component` with body `{"output":"tab-content.children","outputs":{"id":"tab-content","property":"children"},"inputs":[{"id":"tabs","property":"value","value":"tab-X"}],"changedPropIds":["tabs.value"]}` — a 200 per tab is the server-side equivalent of clicking it (same shape with `analytics_sub_content`/`analytics-sub-tabs` exercises the Legacy sub-tabs). Note: duplicate callback OUTPUTS would already fail at `create_dash_app()`, so registration success is itself half the dup check.

**Zero-network-import rule (WS5):** callbacks modules must import with NO network I/O and NO thread starts. Lazy pattern: module-level singleton in the utils module (`websocket_manager.start_if_needed(key, secret)` → None on missing keys, cheap no-op once running) called from inside the callback branch that needs it. To PROVE it: monkeypatch `socket.socket.connect` + `socket.create_connection` to raise, then import — do NOT replace the `socket.socket` class itself (ssl subclasses it at import → TypeError).
